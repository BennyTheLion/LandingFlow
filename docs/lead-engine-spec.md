# LandingFlow Lead Engine — מפרט פרויקט

> מערכת אוטומטית לאיתור עסקים, בדיקה טכנית, ניקוד, מציאת איש קשר והכנת פנייה — עם **אישור אנושי חובה** לפני כל שליחה.

**גרסה:** 1.0
**בעלים:** LandingFlow (landingflow.co.il)
**קצב יעד:** 20–30 עסקים בשבוע

---

## 1. מטרה

להפוך את התהליך הידני של "מצא עסק → בדוק אתר → מצא איש קשר → שלח סרטון" לצינור (pipeline) אוטומטי, כך שהזמן האנושי היחיד שמושקע הוא:

1. הקלטת סרטון Loom (2–3 דק')
2. לחיצה על "אשר ושלח"

**מה שהמערכת לא עושה:** לא שולחת שום דבר בלי אישור מפורש. אין מצב auto-send. זו החלטת מוצר, לא מגבלה טכנית.

## 2. עיקרון מנחה — שימוש חוזר בקיים

באתר כבר קיימים:

| רכיב קיים | שימוש בפרויקט |
|---|---|
| `/audit` — מנוע בדיקת אתרים | **מנוע הליבה.** לא בונים בדיקה חדשה — עוטפים את הקיים ב־API פנימי |
| מערכת משתמשים (`/login`) | הרשאות לאדמין פאנל |
| CRM ולידים | טבלת ה־prospects מתחברת אליו; ליד שהגיב הופך ללקוח פוטנציאלי ב־CRM |
| אינטגרציית וואטסאפ | שלב 2 — ערוץ שליחה נוסף |
| מסד נתונים קיים | טבלאות חדשות באותו DB |

**משימה ראשונה למפתח:** לחשוף את לוגיקת ה־audit כפונקציה/שירות פנימי `runAudit(url) → AuditResult`, כך ששני הצרכנים (עמוד ה־audit הציבורי + ה־Lead Engine) קוראים לאותו קוד.

   │  → status: approved → sent                   │

## 5. Stage 1 — איסוף עסקים

### מקור A: Google Places API (עיקרי, אוטומטי)
- `Text Search` עם שאילתות מובנות: `{niche} {city}`
- מסננים: `rating >= 4.0`, `user_ratings_total >= 30`, קיים `website`
- מ־`Place Details` שולפים: שם, טלפון, אתר, כתובת
- **עלות:** ~$32 ל־1,000 חיפושים. בקצב שלך — כמה דולרים בחודש. הגדר תקציב יומי ב־GCP.

### מקור B: ספריית המודעות של מטא (ידני ב־v1)
ה־Ad Library API דורש אישור אפליקציה, וסקרייפינג של הממשק מפר את תנאי השימוש.
**פתרון v1:** מסך באדמין `+ הוסף ליד ידנית` עם שדה `spends_on_ads = true`. אתה עובר בספרייה 15 דקות בשבוע ומזין 8–10 עסקים. אלה הלידים החמים ביותר, שווה את הזמן הידני.

### מקור C: ייבוא CSV
העלאת קובץ עם `business_name, url, phone, city, niche` → נכנס לצינור.

### כללי דה־דופליקציה
- `domain` הוא ייחודי
- אם קיים prospect עם אותו דומיין ב־90 הימים האחרונים → דלג ורשום ביומן
- דומיין ב־`do_not_contact` → נחסם לצמיתות

## 6. Stage 2 — בדיקה וניקוד

### מקורות הבדיקה
- **PageSpeed Insights API** (חינם, 25k/יום עם מפתח) — ביצועים, SEO, נגישות, best-practices
- **פטצ' HTML של דף הבית** — בדיקת `fbq`, `gtag`, `tel:`, viewport, הצהרת נגישות, טופס
- **בדיקת SSL/כותרות** — תוקף תעודה, HSTS, `X-Frame-Options`

### נוסחת ה־hot_score

הניקוד מודד **כמה שווה לפנות**, לא כמה האתר טוב. ציון גבוה = הזדמנות טובה.

```
hot_score =
    (100 - perf_mobile)        × 0.30    // אתר איטי = כאב מיידי
  + (100 - a11y_score)         × 0.20    // נגישות = חשיפה משפטית
  + (no_analytics ? 100 : 0)   × 0.15    // מפרסם בעיוורון
  + (no_a11y_statement ? 100:0)× 0.15
  + (100 - seo_score)          × 0.10
  + (no_click_to_call ? 100:0) × 0.10

בונוס: spends_on_ads → ×1.4  (חותכים ב־100)
```

**סף כניסה לצינור:** `hot_score >= 55`. מתחת לזה — `status = closed`, לא מבזבזים עליו זמן.

### `primary_issue` — הבעיה שנמכור
נבחרת לפי סדר עדיפות (הראשונה שמתקיימת):
1. `broken_form` — טופס לא מגיב *(דורש בדיקה ידנית, ראה אזהרה ב־§11)*
2. `no_analytics_with_ads` — מפרסם בלי מעקב המרות
3. `slow_mobile` — `perf_mobile < 40`
4. `no_accessibility` — אין הצהרה + ציון נגישות נמוך
5. `no_click_to_call`
6. `weak_seo`

זו הכותרת של הסרטון ושל שורת הנושא במייל.

## 7. Stage 3 — מציאת איש קשר

סדר ניסיונות (עוצרים בהצלחה ראשונה):

1. **סקרייפ עמודי `/contact`, `/about`, `/אודות`, `/צור-קשר`** — regex למייל וטלפון, וחילוץ שם באמצעות LLM מטקסט העמוד
2. **JSON-LD / schema.org** בדף הבית — לעיתים מכיל `founder` / `employee`
3. **Google Places** — טלפון בלבד
4. **fallback:** `info@domain` + דגל `contact_name = null`

**כלל איכות:** prospect ללא `contact_name` יורד לתחתית התור. "היי דני" מול "שלום רב" זה הפרש של פי כמה בשיעור תגובה.

**כבוד ל־robots.txt:** rate limit של בקשה אחת ל־2 שניות לדומיין, User-Agent מזוהה (`LandingFlowBot/1.0 (+https://landingflow.co.il)`).

## 8. Stage 4 — טיוטה + תסריט סרטון

### פלט א': טיוטת ההודעה
קריאה ל־LLM עם נתוני האודיט. הפרומפט מחייב:
- פתיחה בשם פרטי
- הבעיה בשורה הראשונה, לא הצגה עצמית
- מספר קונקרטי אחד מהאודיט
- CTA רך: "אשמח לשלוח את הרשימה המלאה, גם אם לא נעבוד יחד"
- מקסימום 60 מילים בוואטסאפ, 90 במייל
- **אסור:** סופרלטיבים, "אנחנו סוכנות מובילה", אימוג'ים מעבר לאחד

### פלט ב': `video_brief` — התסריט שלך
זה החלק שחוסך הכי הרבה זמן. המערכת מייצרת כרטיס שאתה קורא ממנו בזמן ההקלטה:

```
עסק: מרפאת שיניים ד"ר כהן | דומיין: cohen-dental.co.il
איש קשר: יוסי | מפרסם בפייסבוק: כן

0:00-0:10  "היי יוסי, ראיתי את המודעות של המרפאה, נכנסתי לאתר"
0:10-0:90  הראה: PageSpeed מובייל = 31. טען את האתר בטלפון בשידור חי.
           הצבע על: אין פיקסל פייסבוק בקוד.
0:90-2:30  "אתם משלמים על מודעות, אבל אין מעקב — אתם לא יודעים
            איזו מודעה מביאה מטופל. ובנוסף 4.2 שניות טעינה,
            שזה בערך 40% שעוזבים לפני שהדף נפתח."
2:30-3:00  "הכנתי רשימה מלאה, אשמח לשלוח בחינם."

טאבים לפתוח מראש: [PageSpeed report] [האתר] [view-source]
```

## 9. Stage 5 — אישור ושליחה

### מייל יומי (08:00, ימים א'–ה')
נושא: `4 לידים מוכנים לאישור — hot score ממוצע 71`

לכל ליד בכרטיס: שם עסק, ניקוד, הבעיה, איש קשר, טיוטת ההודעה, ושלושה כפתורים:
`👁 פתח בפאנל` · `✅ אשר ושלח` · `❌ דחה`

### ⚠️ כלל אבטחה קריטי
**כפתור במייל אף פעם לא שולח ישירות.** סורקי אבטחה ותוספי מייל עושים prefetch לקישורים — זה יגרום לשליחות לא מכוונות.

הזרימה הנכונה:
```
כפתור במייל (GET + טוקן חתום)
   ↓
עמוד אישור בפאנל — מציג תצוגה מקדימה סופית
   ↓
לחיצה על "שלח עכשיו" (POST + CSRF)
   ↓
שליחה בפועל
```

הטוקן: חתום (HMAC), חד־פעמי, תוקף 72 שעות, קשור ל־draft_id ספציפי.

### חסמי בטיחות (guardrails)
- **חובה `video_url`** לפני אישור — אין שליחה בלי סרטון
- מקסימום **8 שליחות ביום**, מינימום 5 דקות בין שליחות
- חלון שליחה: א'–ה', 09:00–18:00 שעון ישראל בלבד
- בדיקת `do_not_contact` שנייה לפני השליחה בפועל
- כפתור **"עצור הכל"** בפאנל שמקפיא את כל השליחות

### פולואפים
נוצרים כמשימות ב־`outreach_events`, ומופיעים במייל היומי לאישור — לא נשלחים אוטומטית:
- **יום 3:** "רוצה שאשלח את הרשימה הכתובה?"
- **יום 7:** ערך חדש — צילום מסך של מתחרה שעושה את זה נכון
- **יום 14:** הודעת סגירה — "מניח שזה לא בעדיפות, אני סוגר את הקובץ"

כל תשובה מהליד → `status = replied` → הפולואפים מבוטלים אוטומטית.

## 11. שיקולים משפטיים ואתיים ⚠️

**זה לא ייעוץ משפטי — כדאי להתייעץ עם עו"ד לפני הפעלה.** הנקודות שחייבות תשומת לב:

1. **סעיף 30א לחוק התקשורת ("חוק הספאם")** — מגביל שליחת דבר פרסומת במייל/SMS/פקס ללא הסכמה מראש. החוק חל גם על נמענים עסקיים. בפועל, פנייה ראשונה בעלת אופי מסחרי לכתובת עסקית היא אזור אפור שנשען על פרשנות. **מסקנה מעשית:** ככל שהפנייה נראית יותר כמו "מצאתי תקלה אצלך" ופחות כמו "קנה ממני", המצב טוב יותר — אבל אל תסתמך על זה בלי בדיקה.
2. **כל הודעה חייבת לכלול** אפשרות הסרה ברורה ופרטי שולח מזוהים.
3. **בקשת הסרה = הוספה מיידית ל־`do_not_contact`**, אוטומטית, בלי שאלות.
4. **וואטסאפ עסקי** — הודעות יזומות למספרים שלא פנו אליך קודם מפרות את מדיניות מטא ועלולות לחסום את המספר. אם המספר הזה הוא ערוץ התמיכה הראשי שלך (כמו שמופיע באתר) — **אל תשתמש בו לפנייה קרה.** לפחות בהתחלה, מייל בלבד.
5. **בדיקת טפסים** — מילוי טפסים של עסקים אחרים אוטומטית זו הזרקת נתונים למערכת של אחר. המערכת **לא** תעשה זאת. זו בדיקה ידנית שאתה עושה בעצמך, ומסמן את התוצאה בפאנל.
6. **GDPR/הגנת הפרטיות** — פרטי איש קשר עסקי פומביים הם עיבוד לגיטימי, אבל שמור מדיניות מחיקה: prospect ב־`closed` מעל 12 חודשים → נמחק.

## 12. סטאק מומלץ

לא הצלחתי לזהות בוודאות את הפריימוורק מה־HTML. שתי המלצות לפי המקרה:

**אם האתר Next.js/Node:** הכל באותו פרויקט — API routes ל־pipeline, Vercel Cron או GitHub Actions לתזמון, Prisma למסד. הכי פשוט לתחזוקה.

**אם האתר Laravel/PHP:** Jobs + Queue ל־pipeline, Scheduler ל־cron, Blade או Livewire לפאנל, Eloquent למסד.

**מה שלא הייתי עושה:** לא להוציא את זה ל־n8n/Make. יש לך כבר מסד נתונים ומנוע אודיט — פיצול לשתי מערכות ייצור סנכרון שבור. n8n מצוין לחיבור בין כלים זרים, כאן הכל שלך.

### 12.1 צמצום עלויות נוסף

| פעולה | חוסך | למה |
|---|---|---|
| קאשינג תוצאות `Text Search` לפי `{niche}+{city}` ל־30 יום | Google Places | אין טעם לחפש שוב באותו אזור/נישה כל שבוע אם רוב העסקים כבר ב־DB |
| `Place Details` עם `fields` מצומצם בלבד (name, phone, website, rating, user_ratings_total) | Google Places | שדות מיותרים מייקרים את הבקשה לפי מבנה התמחור של Google |
| Overpass API (OpenStreetMap, חינמי) לנישות/אזורים מכוסים היטב שם | Google Places | תחליף חינמי חלקי, במיוחד לעסקים מקומיים קטנים |
| מודל LLM זול/קטן לטיוטות ול־video_brief (המשימה לא דורשת חשיבה מורכבת) | Anthropic/OpenAI API | טיוטה קצרה בפורמט קבוע — מודל יקר הוא בזבוז |
| Prompt caching אם ה־system prompt/הדוגמאות קבועים בין קריאות | Anthropic/OpenAI API | חוסך טוקנים חוזרים על אותו prompt |
| וידוא שלא נשלח מייל נפרד לכל אירוע מעקב (open/click) | Resend/Postmark | שומר בטווח החינמי (Resend: 3K/חודש, Postmark: 100/חודש) |
| **דה־דופליקציה מחמירה (§5)** | Google Places בעיקר | ההשפעה הגדולה ביותר לאורך זמן — מונע "תשלום חוזר" על אותם עסקים בכל הרצה שבועית |
